== Overview

:url-drehtuer-de: https://drehtuer.de[drehtuer.de^]
:url-drehtuer-net: https://drehtuer.net[drehtuer.net^]
:url-ansible: https://www.ansible.com[Ansible^]
:url-dev-container: https://containers.dev[Development Container^]
:url-vscode: https://code.visualstudio.com[Visual Studio Code^]
:url-invoke: https://docs.pyinvoke.org/en/stable[python-invoke^]

This repo contains the configuration for the hosts link:{url-drehtuer-de}/link:{url-drehtuer-net} as link:{url-ansible} scripts.
The environment is provided as configuration for link:{url-dev-container} and link:{url-vscode}.

The goal is a complete, documentation-as-code setup of the server so that it can be rebuilt or migrated to another host with minimal manual effort. The server runs nginx (serving Nextcloud, with Let's Encrypt certificates), Postfix + Dovecot (with RSpamd for anti-spam filtering, including learning from user feedback), SSH, MariaDB, and Unbound (local DNS caching/resolving), plus supporting system services (firewall, fail2ban, cron, NTP).

Secrets (passwords, private keys, personal data) are never stored unencrypted in this repository — they are encrypted with `ansible-vault`. The vault password itself is kept in `vault/secret.txt`, which is excluded from version control and must never be committed.

Playbooks are run through `tasks.py` (link:{url-invoke}) rather than calling `ansible-playbook` directly, e.g.:

[source, bash]
----
invoke run-playbook --playbook=playbooks/http.yml
----

See `invoke --list` for all available tasks.

== Linting

:url-yamllint: https://yamllint.readthedocs.io/en/stable[yamllint^]
:url-ansible-lint: https://ansible.readthedocs.io/projects/lint[ansible-lint^]
:url-ruff: https://docs.astral.sh/ruff[ruff^]

YAML is checked with link:{url-yamllint} (style, configured in `.yamllint`) and link:{url-ansible-lint} (Ansible practices, configured in `.ansible-lint`, strictest `production` profile).
Python is checked and formatted with link:{url-ruff} (configured in `pyproject.toml`).
All three are installed in the Dev Container.

[source, bash]
----
# Everything
invoke lint
# Apply the fixes the linters can make themselves
invoke lint --fix
# Or one at a time
invoke lint-yaml
invoke lint-ansible
invoke lint-python
----

The same checks run automatically in two places:

* *Before each commit*, via the hook in `.githooks/pre-commit`, which lints the staged YAML and Python files. Git only picks the hook up once per clone:
+
[source, bash]
----
invoke install-hooks
----
+
Use `git commit --no-verify` to bypass it for a single commit.
* *On every push to `main` and every pull request*, via `.github/workflows/lint.yml`.
